# OKF Book Ingest Skill

Convert textbook chapters into OKF concepts — one chapter at a time, as you study it.

## Trigger Patterns

- "ingest book" / "ingest textbook"
- "convert chapter" / "convert chapter X"
- "book to skill" / "textbook to concept"
- "study chapter X from <book>"
- "/book-ingest"
- When okf-study Step 1 (Read/Encode) finds an unstudied chapter

## Dependency

The extraction engine is bundled locally at `tools/book-to-skill/` (MIT license, [upstream](https://github.com/virgiliojr94/book-to-skill)). Install it editable into the vault venv (uv is the vault's Python tool; `.venv/` is gitignored):

```bash
cd tools/book-to-skill && uv pip install -e ".[all]" pymupdf pix2tex timm
```

The CLI lands at `.venv/bin/book-to-skill` — verify with `.venv/bin/book-to-skill --check` (prints a per-format readiness report).

The engine **extracts raw text only** (`full_text.txt` + `metadata.json`). Structured output — `SKILL.md`, `chapters/`, `glossary.md`, `patterns.md`, `cheatsheet.md` — is generated by the agent following `tools/book-to-skill/SKILL.md` Steps 3–9, not by the CLI.

### Page-accurate chapter slices

Text extraction loses math (docling emits `<!-- formula-not-decoded -->` placeholders for formulas; pypdf garbles glyphs). To keep the original pages available for checking, slice the book per chapter BEFORE extraction:

```bash
.venv/bin/python tools/book-slicer.py <book.pdf> [--outdir DIR] [--dry-run]
```

- **PDF with bookmarks** (most modern textbooks, e.g. Serway): chapters sliced exactly from the PDF outline.
- **PDF without bookmarks**: chapter starts detected by heading scan (Arabic, Roman, CJK, Korean, Thai).
- **EPUB**: chapters are already separate spine items — the tool writes a manifest mapping titles → spine items (no physical slice).
- Output: `books/slices/<book-slug>/NN-<chapter>.pdf` + `manifest.json`/`manifest.md` (page ranges per chapter). Slices are committed to the vault; originals stay outside the repo.

The slice is the **reference copy**: chapter concepts link to it (`see pages X–Y of the original`) so formulas/figures can always be checked in the real pages.

### Figures (extracted since 2026-08-10)

`--mode technical` (docling) now extracts figure crops: images land in `<book-dir>/.book_to_skill/figures/` and the extracted markdown references them as `![Image](.../figures/image_NNN.png)`. ~39s per chapter, no VLM. When folding a chapter concept, copy relevant figures into the concept's `assets/` folder.

### Formulas — status

Formula-to-LaTeX (docling `do_formula_enrichment`, CodeFormulaV2 VLM) was tested and **rejected**: ~15+ min and 3GB RAM per 30-page chapter, impractical for whole books.

**Working solution — formula snapshots (since 2026-08-10):** `tools/formula-snap.py` locates formulas with docling's fast layout model (no VLM) and crops them from the rendered page as **lossless WebP** (~3 KB each, ~54% smaller than PNG):

```bash
.venv/bin/python tools/formula-snap.py <chapter-slice.pdf> [--outdir DIR] [--format webp|png] [--latex]
```

- Output: `<book>/.book_to_skill/formulas/NNN_fNNN.webp` + `manifest.json` + `formulas.md` (ready-to-paste `![formula](...)` refs)
- `--latex`: OCR each crop to LaTeX with **pix2tex** (~2s/formula, 97MB model, needs `uv pip install pix2tex timm`). `formulas.md` then pairs each image with `$$...$$` (Obsidian renders both). Verified: Shifrin ch1 → 93 formulas, 290 KB, 93/93 LaTeX, 0 errors, 3m7s.
- When folding a chapter concept, copy the relevant formula crops into the concept's `assets/` and embed them — the image IS the math; the LaTeX is the searchable/editable form.
- Format rationale: formulas are text glyphs, not vector paths, so SVG gains nothing (pymupdf's SVG embeds a raster fallback → 60× larger); WebP lossless is the weight-optimal Obsidian-safe choice; AVIF is smaller still but Obsidian/Electron support is spotty.
- Tesseract does NOT produce LaTeX (character OCR only, no math grammar — tested). pix2tex is the math-aware engine.

## INGEST Procedure — Initial Book Setup

Run once when you first start working with a textbook. Creates the parent book concept only.

### Step 1: Run book-to-skill

```bash
.venv/bin/book-to-skill <path-to-pdf> --mode text --install-missing ask
```

(For tables/code/formulas use `--mode technical` — slower, needs docling. Extraction output goes to `$BOOK_SKILL_WORKDIR`, default `/tmp/book_skill_work/`; set that env var to a scratch dir you control. The CLI prints a token estimate and the output paths.)

This generates:
- `full_text.txt` — combined extracted text
- `metadata.json` — pages/words/tokens, per-source info, chapter structure

The agent then follows `tools/book-to-skill/SKILL.md` Steps 3–9 to generate, into a working directory:
- `SKILL.md` — book overview
- `chapters/` — one file per chapter
- `glossary.md` — key terms
- `patterns.md` — recurring patterns
- `cheatsheet.md` — quick reference

### Step 2: Create the Parent Book Concept

Create `concepts/learning/<domain>/textbooks/<book-slug>.md` if it doesn't exist.

**Frontmatter:**
```yaml
---
type: reference
visibility: shareable
title: "<Book Title>"
description: "<Author>'s <level> <subject> textbook — <one-sentence positioning>."
domain: learning
tags: [<subject>, textbook, <relevant-topics>]
source:
  - isbn:<ISBN>
timestamp: <today>
status: active
author: <Author Name(s)>
level: <undergraduate|graduate|introductory>
progress: 0.0
last-studied: null
next-chapter: <first chapter title>
review-score: null
---
```

**Body sections (mirror existing textbook concepts):**
- Prerequisites
- Topics Covered (list all chapters with numbers)
- Problem Sets (if applicable)
- Study Progress (0/X chapters, not yet started)
- Related (cross-link to roadmap, prerequisite textbooks, okf-study)

### Step 3: Store Generated Files for Reference

Move `glossary.md`, `patterns.md`, `cheatsheet.md` into `concepts/learning/<domain>/textbooks/<book-slug>/` for later chapter-by-chapter conversion.

**DO NOT convert all chapters at once.** The parent concept lists topics; actual chapter concepts are created one-by-one during study.

## CHAPTER Procedure — Convert a Single Chapter

**This is the primary use case.** Run when you are actively studying a chapter.

### Step 1: Identify the Chapter

From the parent book concept's "Topics Covered" list, identify which chapter you're studying. Confirm with the user if ambiguous.

### Step 2: Read the Chapter Slice (and extracted text)

Open the chapter's page-accurate slice (see Page-accurate chapter slices above): `books/slices/<book-slug>/NN-<chapter>.pdf`. Use it for formulas/figures/page numbers; use `full_text.txt` (or the generated `chapters/NN-*.md` if already produced) for readable prose. Reference the slice in the chapter concept's frontmatter/body: `source: slice pages <start>–<end>`, plus a body link to the slice path.

### Step 3: Create the Chapter Concept

Create `concepts/learning/<domain>/textbooks/<book-slug>/<chapter-slug>.md`.

**Frontmatter:**
```yaml
---
type: topic
visibility: shareable
title: "<Chapter Number>: <Chapter Title>"
description: "<1–2 sentence summary of the chapter's core content>."
domain: learning
tags: [<subject>, <chapter-topic-tags>]
source:
  - <book-concept-path>
timestamp: <today>
status: active
---
```

**Body — summarized ~500–1000 words:**
- Core ideas in your own words (not a verbatim copy of the chapter file)
- Key definitions and formulas (if applicable)
- Connections to other concepts in the vault
- What was clear, what needs more work
- Link to parent: `[<Book Title>](/concepts/learning/<domain>/textbooks/<book-slug>.md)`

### Step 4: Cross-Link

1. **Parent book** — add chapter link to parent concept's Study Progress section
2. **Methodology concepts** — link to relevant study methods if applicable (e.g., [Feynman Technique](/concepts/learning/methods/feynman-technique.md) if the chapter was learned via Feynman)
3. **Related concepts** — search the vault for neighboring topics and add bidirectional links
4. **Roadmap** — if the textbook is on a roadmap, update progress

### Step 5: Update Parent Progress

In the parent book concept, update:
- `progress: <chapters-done>/<total-chapters>`
- `last-studied: <today>`
- `next-chapter: <next unconverted chapter title>`

### Step 6: Convert Supplementary Files (If Relevant)

If this chapter drew heavily on glossary terms, patterns, or cheatsheet material:

| Output | OKF type | Path | When to create |
|--------|----------|------|----------------|
| Glossary | `reference` | `concepts/learning/<domain>/textbooks/<book-slug>/glossary.md` | After 3+ chapters reference shared terms |
| Patterns | `playbook` | `concepts/learning/<domain>/textbooks/<book-slug>/patterns.md` | After patterns recur across chapters |
| Cheatsheet | `reference` | `concepts/learning/<domain>/textbooks/<book-slug>/cheatsheet.md` | After 5+ chapters or at midterm |

These are cumulative — append to them as you study, don't recreate each time.

## Guardrails

1. **Never batch-convert an entire book.** Convert chapters one at a time, only as you study them. Reading a chapter without converting it is fine; converting a chapter you haven't read is not.
2. **Chapter concepts are summarized, not copied.** 500–1000 words capturing the essential ideas. The book-to-skill output is a source to distill from, not to paste.
3. **Always link to the parent book concept.** Every chapter concept must link back; the parent must list its chapters.
4. **Always link to the textbook concept on the roadmap.** If the book is on a study roadmap, the chapter should be reachable from there.
5. **No orphan chapters.** Every chapter concept must have at least one inbound link (from the parent book concept, at minimum).

## Integration with okf-study

In the [okf-study](/skills/okf-study/SKILL.md) loop, **Step 1: Read/Encode** is where this skill activates:

- If studying from a textbook and the chapter isn't in the vault → run the CHAPTER procedure
- If the parent book concept doesn't exist yet → run the INGEST procedure first
- The chapter concept becomes the study material for Steps 2–5 of the study loop
- After studying, update the chapter's `timestamp` per the study scoring (✅ = today, 🟡/❌ = unchanged)

## Post-Conversion

After creating or updating any concept:
1. `python3 tools/okf.py index`
2. `python3 tools/okf.py relink --dry-run` (apply if safe)
3. Append to `log.md`
